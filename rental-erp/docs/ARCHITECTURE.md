# 임대관리 ERP — 설계

## 1. 목표

대표자가 로그인해서 **대시보드 하나로 5초 안에** 임대사업 전체 상태를 파악한다.
첫 화면 맨 위에서 ① 오늘 받을 돈 ② 미납금 ③ 계약 만료 예정 ④ 이번 달 수익 ⑤ 대출이자 ⑥ 전체 순수익을 본다.

색 규칙: **문제 → 빨강**, **주의 → 주황/노랑**, **정상 → 초록**, 중요한 숫자는 크게.

## 3. 데이터 구조

```
owners(소유주: 개인/법인)
  └─ properties(부동산) ─┬─ units(호실: 동·층·호, 예상 월세, 공실 시작일)
                        │     └─ contracts(계약: 임차인, 기간, 보증금, 월세, 관리비, 부가세, 납부일, 상태, 특약, OCR 원본)
                        │           ├─ deposits(보증금: 받은 금액, 반환 예정일, 반환·일부반환·상계, 미반환)
                        │           ├─ rent_charges(월 청구: 청구월, 납부일, 청구액, 입금 배분액) ── arrears(뷰: 미납)
                        │           └─ payments(입금) ── payment_allocations(입금 → 청구 배분)
                        ├─ loans(대출: 금융기관, 원금, 잔액, 금리, 고정/변동, 상환방식, 만기)
                        │     └─ loan_transactions(원금상환 / 이자납부 / 금리변경)
                        ├─ expenses(비용: 12개 구분, 부동산 없으면 공통 비용)
                        └─ documents(문서: PDF/JPG/PNG, 부동산·계약·임차인·대출에 연결)
tenants(임차인) ── contracts
users(관리자/직원/조회자) · notifications(알림) ── notification_deliveries(문자·카톡·이메일·웹훅 발송)
settings(계산식·기준값·알림 받을 곳) · audit_logs(변경 이력)
```

- **부동산 1개 = 여러 호실**, 호실마다 임차인·보증금·월세·계약기간이 다르다.
- **소유주(개인/법인)** 를 부동산에 연결 → 부동산별 / 법인별 / 전체 통합 손익.
- 금액은 원 단위 정수(bigint), 날짜는 date.
- SQL: `db/migrations/0001_init.sql`

## 4. 자동 계산 (lib/engine.ts — 순수 함수, 단위 테스트 있음)

| 항목 | 계산 |
|---|---|
| 월세 자동 청구 | 청구 시작 월(없으면 계약 시작 월)부터 이번 달까지 매월 1건, 납부일(31일→말일 보정). 매일 자동 생성 |
| 입금 배분 | 입금일 순서, 지정한 청구월 먼저 → 남으면 가장 오래된 미납부터. 남는 금액은 선납 |
| 미납 | 청구액 − 입금액 (납부일이 지난 것). 미납기간 = 가장 오래된 미납 납부일부터 오늘까지 → 1~30 / 31~60 / 61~90 / 90일 이상 |
| 계약 만료 | 30일 이내 🔴, 60일 🟠, 90일 🟡. 알림 90·60·30·7일 전 |
| 월 이자 | 잔액 × 금리 ÷ 12 (설정: 일할 계산) — 10억 × 5% → 월 4,166,667원 |
| 월 운영비 | 최근 12개월 실제 비용(대출이자 제외) ÷ 12 |
| 월 순수익 | 월세수입 + 기타수입(관리비) − 운영비 − 대출이자 *(설정에서 식 수정)* |
| 연 순수익 | 월 순수익 × 12 *(설정에서 식 수정)* |
| 자기자본 | 매입가 + 취득비 + 리모델링 + 기타 − 대출잔액 − 보증금 *(설정에서 식 수정)* |
| 단순 임대수익률 | 연간 임대수익 ÷ 매입가격 × 100 |
| 대출이자 반영 수익률 | (연간 임대수익 − 연간 이자 − 연간 운영비) ÷ 자기자본 × 100 |
| 실제 현금수익률 | 최근 12개월 (받은 돈 − 쓴 돈) ÷ (투자 총액 − 대출 원금 + 갚은 원금 − 보증금) × 100 |
| 공실 손실 | 예상 월세 ÷ 30 × 공실일수 *(설정에서 식 수정)* |
| 시뮬레이션 | 월세 ±%, 금리 ±%p, 운영비 ±%, 추가 공실% → 연 이자·순수익·수익률 변화 |
| 투자 의사결정 | 필요 자기자본, 월 현금흐름, 연 순수익, 임대수익률, 자기자본 수익률, 이자 부담률, 손익분기 월세·임대율, 회수기간 |

계산식은 `lib/formula.ts` 의 안전한 수식 계산기(사칙연산·괄호·min/max, eval 사용 안 함)로 실행된다.

## 5. AI

- **계약서 OCR** (`/api/ocr`): 업로드 → 원본을 문서함에 저장 → Claude 가 구조화된 JSON 으로 추출 →
  기존 호실·임차인 자동 매칭 → 입력칸 자동 채움 → **"AI가 추출한 계약정보입니다. 저장하기 전에 확인해주세요."** + 확인 체크 필수
- **AI 질문** (`/assistant`): 계산이 끝난 장부 요약(JSON)만 근거로 답한다. 키가 없어도 자주 묻는 질문(최고 수익 건물, 미납, n개월 내 만료, 이자 제외 순수익, 월세 n% 인상, 금리 인상, 공실)은 규칙 기반으로 답한다.
- AI 가 읽는 데이터는 `snapshotForAI()` 한 곳에서 만든다 → 기능을 늘릴 때 여기만 고치면 된다.

## 6. 권한

| 권한 | 할 수 있는 일 |
|---|---|
| 관리자 | 모든 정보 확인·수정, 부동산·호실·대출·비용·소유주, 사용자·설정, 삭제, 엑셀 가져오기 |
| 직원 | 임차인·계약·월세 입금·청구 조정·보증금·문서 업로드 |
| 조회자 | 조회만 |

버튼은 권한에 맞게 숨기고, 서버에서도 모든 저장 동작마다 권한을 다시 확인한다.

## 7. 알림

`lib/jobs.ts runDaily()` — 매일 아침(Vercel Cron, 한국시간 07:00) 월세 청구 생성 → 알림 생성(같은 알림은 한 번만).
`notification_deliveries` 에 채널별 발송 기록. 문자·카카오·이메일 업체는 `lib/notifications.ts` 의 `PROVIDERS` 에 구현을 넣으면 된다 (웹훅은 바로 동작).
