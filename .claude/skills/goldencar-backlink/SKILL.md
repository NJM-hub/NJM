# GOLDENCAR 백링크 큐

하루 1건, 국가별 언어·키워드로 외부 플랫폼에 올릴 글을 만들고, 게시 후 링크를 검증해 기록한다.
사용자는 글을 직접 복사해 수동 게시한다. 자동 게시·대량 게시는 하지 않는다.

같은 폴더의 파일:

| 파일 | 내용 |
|---|---|
| `presets.md` | 언어별 키워드 프리셋, 랜딩 URL 배정, 앵커 후보 |
| `playbook.md` | 플랫폼별 제목·본문·링크·태그 규칙 (버전 관리) |
| `facts.md` | 글에 써도 되는 골든카 사실 목록 (출처·확인일) |
| `queue-log.csv` | 작업 기록. 큐 실행·게시·검증 때마다 갱신 |

## 명령어

| 사용자 입력 | 동작 |
|---|---|
| `대만 큐` `홍콩 큐` `간체 큐` `일본어 큐` `태국어 큐` `베트남어 큐` `영어 큐` | 해당 언어로 글 1건 생성 |
| `○○ 큐 미디엄` (언어 + 플랫폼) | 플랫폼을 지정해 생성 |
| `오늘 큐` | `presets.md`의 요일 로테이션대로 언어·플랫폼을 골라 생성 |
| `게시 완료 GC-… https://…` | 게시 URL 기록 후 링크 검증 |
| `큐 검증 GC-…` | 이미 기록된 건을 다시 검증 (색인 확인 포함) |
| `큐 현황` | 로그 집계 보고 |

별칭: 번체=대만, 중국/중문=간체, 일본=일본어, 태국=태국어, 베트남=베트남어, 글로벌/English=영어.

## 큐 실행 절차 (`○○ 큐`)

1. `queue-log.csv`를 읽는다. 같은 언어의 최근 기록으로 플랫폼·키워드·랜딩·앵커 유형을 정한다.
   - 플랫폼: 그 언어에 맞는 플랫폼 중 가장 오래 안 쓴 것 (`presets.md` 언어별 플랫폼 칸).
   - 키워드: 최근 5건에서 메인으로 쓴 키워드는 피한다.
   - 랜딩: 키워드에 배정된 URL. 같은 랜딩이 3건 연속이면 다른 서비스 키워드로 바꾼다.
   - 앵커: 최근 5건의 앵커 유형 분포를 보고 부족한 유형을 쓴다. 정확 일치 키워드는 2건 연속 쓰지 않는다.
2. 랜딩 URL을 `curl -sS -o /dev/null -w "%{http_code} %{redirect_url}"`로 확인한다. 200이 아니면 결과에 그대로 적는다.
3. `playbook.md`의 해당 플랫폼 규칙과 `facts.md`의 사실만으로 글을 쓴다.
   - 그 나라 사람이 쓴 것처럼 자연스러운 현지어. 번역투 금지.
   - 다른 날 같은 플랫폼에 쓴 글과 주제·도입부가 겹치지 않게 한다 (로그의 제목 확인).
   - `facts.md`에 없는 가격·차종·운영시간·후기·수상 내역은 쓰지 않는다.
4. 아래 출력 형식으로 답한다.
5. `queue-log.csv`에 한 줄 추가: `status=작성완료`, 나머지 검증 칸은 비운다. 커밋은 사용자가 요청할 때만.

## 출력 형식

설명은 한국어, 복사할 내용은 각각 별도 코드블록. 순서:

1. 요약 표: 큐 ID, 언어/국가, 플랫폼, Target URL(+상태코드), 메인 키워드, 연관 키워드, 앵커 유형·앵커 텍스트
2. `제목` 코드블록
3. `본문` 코드블록 — 링크 자리는 `[앵커 텍스트](URL)` 형식으로 표시하고, 플랫폼이 마크다운을 지원하지 않으면 "링크 넣는 위치" 안내를 따로 쓴다
4. `태그/해시태그` 코드블록
5. 플랫폼별 추가 칸 (예: Medium 부제, Blogger 검색 설명, Pinterest 설명, 이미지 alt)
6. 게시 체크리스트 3~5줄과 다음 명령 안내: `게시 완료 {큐ID} {게시URL}`

큐 ID 형식: `GC-YYYYMMDD-{언어코드}-{플랫폼코드}` 예: `GC-20261029-JA-MED`
- 언어코드: TW HK CN JA TH VI EN
- 플랫폼코드: `playbook.md` 표의 코드

## 게시 완료 처리 (`게시 완료 GC-… URL`)

1. 게시 URL을 curl로 연다 (UA는 일반 브라우저).
   - 공개 여부: 200이면 공개, 401/403/로그인 페이지면 `수동 확인 필요`.
   - 링크 존재: HTML에 `goldencar.co.kr` 링크가 있는지, 대상 URL이 맞는지.
   - 링크 속성: `rel` 값 (nofollow / ugc / sponsored / 없음) 기록.
   - LinkedIn·Facebook처럼 로그인 없이 본문이 안 보이면 추측하지 말고 `수동 확인 필요`로 두고, 사용자에게 확인할 3가지(공개 범위, 링크 클릭 시 이동 주소, 링크 미리보기)를 묻는다.
2. 로그 갱신: `post_url`, `published_at`, `public_check`, `link_present`, `link_clickable`, `link_rel`, `link_target_ok`, `verified_at`, `status`.
   - 모두 확인되면 `status=검증완료`, 일부만 확인되면 `status=게시완료`.
3. 같은 플랫폼에 같은 랜딩으로 간 링크가 이미 있으면 `중복`으로 notes에 적는다.

## 색인 확인 (`큐 검증 GC-…`)

게시 7일 이후 권장. 웹검색으로 `site:` 또는 게시 URL·제목을 검색해 보이면 `index_status=색인됨`, 안 보이면 `미확인`.
검색 도구 결과만으로 단정하지 말고 "검색 결과에서 확인됨/확인 안 됨"으로 적는다.

## 큐 현황 (`큐 현황`)

로그에서 집계: 작성 수, 게시 수, 공개 확인 수, 정상 링크 수, 중복 수, rel 분포, 색인 확인 수, 언어별·플랫폼별·랜딩별 건수.
유입·전환은 로그에 없으므로 GA/서치콘솔 수치를 사용자가 줄 때만 적는다.

## 금지

- 검색량, 순위 상승, 색인을 보장하거나 추정 수치를 사실처럼 쓰지 않는다.
- 고객 후기를 지어내거나 고객인 척하는 글을 쓰지 않는다. 글쓴이는 골든카 또는 여행 정보 작성자로, 골든카 링크임이 드러나게 한다.
- 커뮤니티(그룹·카페·포럼)는 그곳 규칙상 홍보가 허용될 때만. 모르면 `검증 필요`로 표시하고 쓰지 않는다.
- Reddit은 운영 대상이 아니다.
